# Domain glossary — manga colorization

Terms used across the repo's methods, pipeline, and evaluation. Glossary only;
no implementation details.

- **Eval case**: one fixed scenario in the pipeline's evaluation set
  (DET-*, OOV-*, COL-*, LAY-*, SIZE-*). A durable input plus the expected
  outcome; the unit the real-network integration suite parametrizes over.
- **Known-failing case**: an eval case that asserts the *correct* behavior
  and is expected to fail on a live run until the underlying pipeline bug is
  fixed. Tracked in the eval set and documented; never xfailed.
- **Detection mode**: the way the character detector is invoked for a page or
  panel (page-level, panel-only, panel-plus-page, panel-plus-page-with-cast).
  Implemented as a **detection strategy**; distinct from a
  character-detection *method* (a self-contained research experiment under
  `research/character_detection_methods/`).
- **Detection strategy**: one class per detection mode (strategy design
  pattern) behind a uniform per-page interface returning a per-panel record
  set; the detector is the context and dispatches through `detect(mode, …)`.
  The panel-only strategy is also the cropped-panel fallback prompt of the
  page-context strategies.
- **Committed test input**: fixed input files under the pipeline's test data
  directory, regenerated by a dedicated script; the integration suite never
  derives them from raw sources at test time.
- **Crop-stability tripwire**: the check that live panel extraction still
  reproduces the committed crops byte-for-byte, guarding the eval cases'
  panel references against detector/ordering drift.
- **Failure taxonomy**: the shared vocabulary classifying eval-case failures
  (known-character-confusion, out-of-vocabulary, palette-adherence,
  palette-geography, zero-panel-fallback, blank-page-skip,
  oversized-input-capping, …), reused across the eval set, the integration
  suite, and the comparison docs.
- **Color verdict**: the structured output (`analyse: str`, `good_color: bool`)
  returned by the OpenRouter vision-language model (`openai/gpt-5.6-luna`,
  strict json_schema) for the COL-* eval cases — one generic judgment of
  whether every character in the colorized panel has its canonical Frieren
  palette, with no fixture expectations rendered into the prompt. It does not
  itself distinguish palette *adherence* from palette *geography*; that
  distinction lives at the case level in the fixture's `failure` tag.
