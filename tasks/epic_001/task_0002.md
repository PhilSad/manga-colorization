# Task 0002 — Panel detection with YOLO26n + Japanese reading-order numbering

> **Status: ✅ DONE** (implemented, tests green, committed as `96bc41f`; real-model check: 5 panels detected on 0134-004)

## Goal

Implement pipeline stage 1 (+ the numbering logic shared with stage 2):
- `detection.py`: a `PanelDetector` protocol and a `YoloPanelDetector` implementation
  wrapping the HuggingFace model `leoxs22/manga-panel-detector-yolo26n`
  (`manga_panel_detector_fp32.pt`, YOLO26-nano via `ultralytics`, classes
  `0: panel`, `1: text`; recommended `conf=0.25`).
- `panel_ordering.py`: a pure function assigning Japanese reading order (right-to-left,
  top-to-bottom) to detected boxes.

Detected boxes + reading order are persisted as `panels.json` per page (used by
extraction in task_0003 and stitching in task_0007). A debug overlay image (page with
numbered boxes drawn) is written next to it.

## Context

Model card (Apache-2.0): https://huggingface.co/leoxs22/manga-panel-detector-yolo26n
The `.pt` file is a standard ultralytics checkpoint; the repo also ships an INT8
TFLite variant — we use the FP32 `.pt` for accuracy. We only keep class `0` (panel);
`text` boxes are ignored. Model weights are downloaded once into `pipeline_v1/models/`
(gitignored) — never committed.

## Design

### `detection.py`

```python
@dataclass
class PanelBox:
    x1: float; y1: float; x2: float; y2: float
    confidence: float

class PanelDetector(Protocol):
    def detect(self, page: Path) -> list[PanelBox]: ...

class YoloPanelDetector:
    def __init__(self, model_path: Path | None = None, conf: float = 0.25): ...
```

- `model_path` defaults to `pipeline_v1/models/manga_panel_detector_fp32.pt`; if
  missing, download it from the HF repo (`https://huggingface.co/.../resolve/main/...`)
  with `urllib` or `huggingface_hub` (stdlib `urllib` is fine, no new dep).
- `ultralytics` is imported lazily inside `detect()` so offline tests / other steps
  never require torch.
- Predict at the model's native `imgsz=640`; keep only `cls == 0` boxes above `conf`.

### `panel_ordering.py`

```python
def reading_order(panels: Sequence[PanelBox]) -> list[int]:
    """Return panel indices in Japanese reading order (right-to-left, top-to-bottom)."""
```

Algorithm (band clustering):
1. Sort panels by `y1` ascending.
2. Greedily cluster into horizontal bands: a panel joins the current band if its
   y-interval overlaps the band's y-interval by more than a threshold
   (`overlap / min(height) > 0.3`).
3. Sort bands by their top edge; within each band sort by `x1` descending
   (rightmost first).
4. Concatenate band order → indices 1..N.

The clustering threshold lives as a named constant so tests can pin it.

## Tests (`test_panel_ordering.py`)

Synthetic layouts with known expected order:
- 2×2 grid (rows top→bottom, each row right→left).
- Right column with two stacked small panels + one tall left panel.
- Horizontal title/banner panel across the top + two panels below.
- Nested/overlapping boxes are not expected from the model; add one guard test that
  the function still returns a total order without crashing.

`test_detection.py`: monkeypatch `ultralytics.YOLO` to return canned boxes (incl. one
`text` class box that must be dropped, one low-confidence box that must be filtered)
and assert `detect()` output; assert the model file is downloaded on first use
(monkeypatched URL opener).

## Risk note

Python 3.14 is in use; `torch`/`ultralytics` must have compatible wheels for the repo
venv. If not, fallback options (decide during implementation, document in README):
(a) dedicated venv for the detection step — `uv` is installed, e.g.
`uv venv --python 3.13 .venv-panels` — or (b) export the model to ONNX and use
`onnxruntime` instead. The `PanelDetector` protocol isolates this decision; the
orchestrator only ever sees the protocol.
