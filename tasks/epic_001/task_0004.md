# Task 0004 — Per-panel character detection via OpenRouter `google/gemma-4-31b-it`

> **Status: ✅ DONE** (implemented, tests green, committed as `da5f682`; real API validation on `data/panels`: 4/4 ok, $0.000333 total)

## Goal

Implement pipeline stage 3: for each extracted panel, call OpenRouter
`google/gemma-4-31b-it` (one image per call, structured JSON answer) and record which
canonical reference characters (from `data/refs/`) appear. Outputs: one JSON per panel
under `2_characters/` plus aggregated per-page records in the manifest, with per-call
cost from OpenRouter `usage.cost`.

## Context

This is a library port of
`research/character_detection_methods/character-detection-openrouter-vlm/run.py`
(reuse its `prompt.txt`, `CHARACTER_HINTS`, JSON contract, parsing/validation, retry
policy, and cost recording). The pipeline needs it as a callable module with a clean
interface so the orchestrator can drive it and tests can mock it — the research script
stays untouched as the standalone experiment.

## Design

```python
class CharacterDetector(Protocol):
    def detect(self, panel: Path, refs_dir: Path) -> CharacterRecord: ...

@dataclass
class CharacterRecord:
    status: str                    # ok | ok-with-unknown | unparseable | error
    characters: list[str]          # canonical names (validated)
    unknown_entries: list[str]
    response_text: str
    usage: dict                    # prompt/completion/total tokens
    cost_usd: float | None
    cost_source: str
    latency_s: float
    error: str | None
```

- Port from the research method: `canonical_characters(refs_dir)` (with the
  `_reference` / `_anime_profile` label cleanup), `build_prompt(template, canonical)`
  with `CHARACTER_HINTS`, `parse_characters`, `validate_characters`,
  `classify_panel`-equivalent with backoff/retry (`RateLimitError`,
  `response_format=json_object` fallback, transient retries, `MAX_ATTEMPTS=8`).
- The step writes `2_characters/<panel_stem>.json` (full record incl. sha256 of the
  panel, model, latency, cost) and aggregates a `2_characters/summary.json`.
- API key from `OPENROUTER_API_KEY` in the repo `.env`; model default
  `google/gemma-4-31b-it`; `--sleep 2` between calls (paid tier, keep small).

## Tests (`test_characters.py` — offline, mocked OpenAI client)

- `parse_characters`: plain JSON, fenced ```json```, trailing prose → same result;
  garbage → `None`.
- `validate_characters`: canonical-casing normalization, dedupe, unknown entries
  collected, names not in the refs list flagged.
- `classify`-equivalent with a monkeypatched `client.chat.completions.create`:
  success path (status `ok`, cost from `usage.cost`), `ok-with-unknown`, rate-limit
  retry then success, permanent error → `status=error` (no exception).
- `canonical_characters` on a tmp refs dir with `frieren_reference.webp` and
  `Frieren_anime_profile.webp` → deduped `["Frieren"]`.
