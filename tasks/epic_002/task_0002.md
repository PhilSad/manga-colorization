# Task 0002 — Add canonical character profiles and explicit FLUX palette conditioning

> **Status: 📋 PLANNED**
>
> Depends on task 0001.

## Goal

Stop relying on FLUX to read atlas labels and infer canonical colors implicitly.
Store structured character profiles and inject the detected characters' identities
and palettes directly into the colorization prompt while retaining the colored atlas
as visual evidence.

## Context

`data/refs/` already contains colored anime character sheets. The V1 failure is in
conditioning: detected names reach the atlas builder, but `FluxColorizer` receives
only the panel path, atlas path, and generic instruction to use image `#2`. At four
steps this is too indirect, and Frieren is repeatedly given magenta hair despite her
silver-haired reference.

## Files

- `pipeline_v1/character_profiles.json` — canonical names, monochrome identity cues,
  palette descriptions, outfit/era variants, aliases, and reference filenames.
- `pipeline_v1/profiles.py` — schema loading, validation, and prompt rendering.
- `pipeline_v1/colorizer.py`, `pipeline_v1/colorizer_prompt.txt` — accept and render
  the selected profiles.
- `pipeline_v1/steps/colorize.py` — pass character identities/profiles into the
  colorizer and manifest.
- `pipeline_v1/characters.py` — replace the duplicated hard-coded hint map with the
  shared profile source.
- Unit tests for profile validation, prompt rendering, and request provenance.

## Design

Each profile should contain at minimum:

```json
{
  "name": "Frieren",
  "identity_cues": ["elf ears", "long twin-tail hair"],
  "canonical_palette": [
    "silver-white hair",
    "green eyes",
    "white coat with gold trim"
  ],
  "reference_files": ["frieren_reference.webp"],
  "variants": {}
}
```

The generated FLUX instruction must explicitly name only the characters assigned to
that panel and state their canonical colors. Atlas construction remains filtered to
the same names. Unknown/unprofiled characters receive a neutral invented palette and
are recorded rather than silently mapped to another character.

Use a fixed experiment seed from task 0001. Compare on the failure set:

1. current generic atlas instruction;
2. atlas plus explicit canonical palette text;
3. if needed, palette text plus alternative atlas/reference layout.

Do not increase the default four FLUX steps unless the controlled comparison shows a
clear benefit.

## Tests

- Duplicate names/aliases and missing reference files fail validation clearly.
- Prompt text contains every selected character and no unselected character.
- No-atlas and unknown-character cases remain supported.
- Manifest records profile schema/hash, rendered palette instruction, atlas hash,
  seed, and output hash.
- Fake-server tests assert that explicit palette text reaches `POST /edit`.

## Acceptance criteria

- [ ] Character identification hints and palettes have one shared source of truth.
- [ ] FLUX receives explicit canonical colors for every profiled detected character.
- [ ] V1.1 evaluation shows a measured improvement over the current prompt on the
      fixed color-adherence cases without more paid calls.
- [ ] README and architecture documentation describe the profile contract.
- [ ] Tests pass and the change is committed.
