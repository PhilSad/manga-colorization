# Task 0003 — Batch character detection once per page with contextual fallback

> **Status: ✅ DONE** (implemented, 175 offline tests green, committed — see the V1.1 implementation commit)
>
> Implemented: page-level detection (`detection_mode="page"` default): one paid call per page on the reading-order-annotated page, strict per-panel JSON contract (`prompt.txt`), validation (expected panel keys only, canonical names, extra keys rejected), cropped-panel fallbacks for missing/invalid/uncertain entries, `chapter_casts.json` cached shortlists (`--cast-key`, deterministic, never fetched remotely), `max_tokens` reduced to 1024, configurable sleep + rate-limit backoff, manifest totals split into page/fallback calls. Per-panel records carry `source` (`page`/`fallback`/`forced`) and `uncertain`.
>
> Depends on tasks 0001 and 0002.

## Goal

Replace one paid character-detection request per panel with one request per page that
maps numbered panels to canonical characters. Preserve a per-panel fallback only for
explicitly uncertain or invalid page-level results.

## Context

The five-page V1 run used 18 OpenRouter calls and cost `$0.00137551`. Each request
repeated roughly the same canonical-character prompt and lost useful dialogue,
neighboring-panel, and flashback context. This contributed to Fern/Stark and
Heiter/Sein confusions.

A complete series roster should not be placed in every prompt: that would increase
tokens and ambiguity. The detector should use a cached chapter cast shortlist when
available, with the full canonical list as a controlled fallback.

## Files

- `pipeline_v1/characters.py` — page-level detector protocol and structured result.
- `pipeline_v1/steps/characters.py` — build one numbered page/contact-sheet request,

- `pipeline_v1/prompt.txt` — page-to-panel JSON contract.
- `pipeline_v1/chapter_casts.json` — optional, cached chapter/arc cast shortlists and
  temporal hints; no network access during a run.
- `pipeline_v1/config.py` — detection mode and fallback controls.
- Character-step, parsing, cost, and end-to-end tests.

## Design

Request a strict mapping such as:

```json
{
  "panels": {
    "panel_0001": {"characters": ["Frieren"], "uncertain": false},
    "panel_0002": {"characters": ["Himmel", "Heiter"], "uncertain": true}
  }
}
```

The input should preserve readable page text and overlay the same panel numbers used
by extraction. Validate that all expected panel keys appear, names are canonical,
and no extra keys are accepted. Only missing, invalid, or `uncertain` entries trigger
a cropped-panel fallback call.

Reduce `max_tokens` from the current 2048 to a measured bounded value appropriate for
the page mapping, and replace the unconditional two-second sleep with rate-limit
backoff or a configurable delay. Record page calls and fallback calls separately.

## Tests

- Structured parsing handles complete, missing, unknown, and malformed panel maps.
- A complete page response produces one paid call and no fallbacks.
- Only uncertain panels generate fallback calls.
- Chapter shortlist selection is deterministic and never fetches remote content.
- Manifest cost totals exactly match page and fallback call records.
