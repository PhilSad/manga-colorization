# Task 0005 — Add optional page-batched color verification and bounded retries

> **Status: 📋 PLANNED / GATED**
>
> Depends on tasks 0001–0003. Implement only if explicit palette conditioning still
> leaves material color-adherence failures.

## Goal

When needed, verify canonical character colors with at most one paid VLM request per
page and re-colorize only the panels that fail. Keep verification disabled by default
and enforce a strict one-retry limit.

## Context

A verifier on every panel would double character-related API calls and could create
unbounded FLUX retries. A page contact sheet can inspect all generated panels at
once. Verification should be a measured fallback, not compensation for an indirect
or ineffective colorization prompt.

## Files

- `pipeline_v1/verification.py` — protocol, OpenRouter implementation, parsing, and
  canonical profile rendering.
- `pipeline_v1/steps/verify.py` — page contact sheets, records, and retry decisions.
- `pipeline_v1/config.py`, `pipeline_v1/orchestrator.py` — optional `verify` stage and
  strict limits.
- `pipeline_v1/verification_prompt.txt`.
- Mock backend, parser, orchestration, retry, and cost tests.

## Design

The verifier receives, for one page:

- numbered colorized panel crops;
- the expected characters and canonical palette text from task 0002;
- optionally compact reference images for those characters only.

Return strict JSON per panel with `pass`, concise failed attributes, and confidence.
Only confident failures are eligible for a retry. A retry receives the failed
attributes as stronger prompt constraints, uses the original monochrome panel as the
edit target, and may happen at most once. The verifier must never edit an already
colorized panel or recursively verify its own retry.

Manifest totals must separate detection, verification, original FLUX, and retry FLUX
calls and costs. A configured per-run paid-cost ceiling must stop optional verification
before exceeding the budget.

## Tests

- One page with multiple panels creates one verifier call.
- Passing/uncertain panels are not regenerated.
- A confident failure is regenerated exactly once; repeated failure cannot recurse.
- Cost ceiling and disabled-by-default behavior are enforced.
- Mock end-to-end run records all decisions and preserves original artifacts.

## Acceptance criteria

- [ ] Task 0001 results justify enabling this feature before implementation proceeds.
- [ ] Verification adds no more than one paid call per processed page.
- [ ] Retry count is bounded to one per panel and all originals remain preserved.
- [ ] Measured quality gain and added API cost are recorded separately.
- [ ] Tests and documentation are complete; commit the implementation.
