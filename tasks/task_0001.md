# Task 0001 — Scaffold the `pipeline_v1` package: config, run context, manifest, CLI skeleton

## Goal

Create the skeleton of the new pipeline package in the existing (empty) `pipeline_v1/`
directory: Python package layout, run-configuration dataclass + argparse CLI, the
timestamped run-directory + manifest machinery (repo conventions), dependency list,
pytest scaffolding, and an `ARCHITECTURE.md` describing the module layout.

## Context

The pipeline (see `inputs_humans/idea.md`) chains 5 stages per manga page:
(1) YOLO26n panel detection, (2) panel extraction numbered in Japanese reading order,
(3) per-panel character detection via OpenRouter `google/gemma-4-31b-it`,
(4) per-panel colorization with FLUX.2 Klein 9B base + manga LoRA on the Spark
inference server (atlas built only from detected characters), (5) stitching the
colorized panels back onto the original page at the recorded positions.

Repo conventions to follow (AGENTS.md): fresh timestamped `output/YYYYMMDD-HHMMSS/`
run dir per invocation, never overwritten; a `manifest.json` recording command,
configuration, inputs, cost data, status; intermediate outputs in numbered
directories prefixed by their pipeline-step index (`1_panels/`, `2_characters/`,
`3_colorized/`, `4_stitched/`); no secrets in code (`.env` at repo root).

## Files

- `pipeline_v1/__init__.py` — package marker (name the package `pipeline_v1`).
- `pipeline_v1/run.py` — executable entry point: parse args, wire real backends, run
  orchestrator (orchestrator arrives in task_0008; for now a `--steps`-aware stub that
  prints the parsed config).
- `pipeline_v1/config.py` — `PipelineConfig` dataclass + `parse_args()` (argparse)
  with validation. All knobs for every step (see Design).
- `pipeline_v1/run_context.py` — `RunContext`: create timestamped run dir
  (`YYYYMMDD-HHMMSS` + `-NN` suffix when colliding), atomic JSON writer, manifest
  init/update helpers, `step_dir(index, name)` helper returning `1_panels/` etc.,
  `iso_now()`.
- `pipeline_v1/requirements.txt` — `pillow`, `numpy`, `requests`, `python-dotenv`,
  `openai`, `tqdm`, `pytest`, `ultralytics` (used lazily by the detector; verify
  Python 3.14 wheel availability — see task_0002 risk note).
- `pipeline_v1/pyproject.toml` — minimal project metadata + `[tool.pytest.ini_options]`
  (`testpaths = ["tests"]`), so `.venv/bin/pytest` works from the repo root.
- `pipeline_v1/.gitignore` — `output/`, `models/`, `__pycache__/`, `*.pyc`.
- `pipeline_v1/tests/conftest.py` — fixtures: `tmp_run_context` (runs in a tmp_path),
  synthetic config fixture.
- `pipeline_v1/tests/test_config.py`, `pipeline_v1/tests/test_run_context.py`.
- `pipeline_v1/ARCHITECTURE.md` — module map + data-flow diagram (see Design).

## Design

```text
pipeline_v1/
├── run.py                # entry point: config -> orchestrator (real backends)
├── config.py             # PipelineConfig + CLI
├── run_context.py        # run dirs, manifest, atomic JSON
├── detection.py          # task_0002: YOLO26n panel detection (protocol + impl)
├── panel_ordering.py     # task_0002: Japanese reading-order (pure function)
├── extraction.py         # task_0003: crop + numbered files (pure function)
├── characters.py         # task_0004: OpenRouter VLM client (protocol + impl)
├── prompt.txt            # task_0004: character-detection prompt (copy of existing method's)
├── atlas.py              # task_0005: labelled atlas from detected characters only
├── colorizer.py          # task_0006: FLUX.2 Klein /edit client (protocol + impl)
├── colorizer_prompt.txt  # task_0006: colorize-only prompt with mngclranm trigger
├── stitching.py          # task_0007: paste colorized panels at recorded boxes
├── orchestrator.py       # task_0008: step sequencing, manifest aggregation, resume
├── mock_backends.py      # task_0008: fake detector / VLM / colorizer (offline e2e)
├── output/<ts>/          # per-run artifacts (gitignored)
│   ├── 1_panels/         # crops + panels.json (boxes + reading order)
│   ├── 2_characters/     # per-panel detection JSONs
│   ├── 3_colorized/      # per-panel colorized outputs
│   ├── 4_stitched/       # final pages
│   └── manifest.json
└── tests/
```

`PipelineConfig` fields (defaults in brackets):
`input_dir` (repo `data/chapter_134`), `refs_dir` (`data/refs`), `output_root`
(`pipeline_v1/output`), `endpoint` (`http://spark:3000`), `vlm_model`
(`google/gemma-4-31b-it`), `vlm_prompt_file`, `max_tokens` (2048), `temperature`
(0.2), `sleep_s` (2.0), `atlas_columns` (ceil(sqrt(n))),
`flux_steps` (20), `guidance_scale` (4.0), `lora_scale` (1.0), `seed`, `output_format`
(png), `skip_first` (0), `limit` (None), `steps` (all), `mock` (False).

## Implementation notes

- Port `create_run_dir`, `write_json`, `iso_now`, and the manifest lifecycle pattern
  from `research/character_detection_methods/character-detection-openrouter-vlm/run.py`
  into `run_context.py` (they are the established conventions).
- `--steps` accepts a comma-separated subset of `panels,characters,colorize,stitch`
  (enables resume in task_0008).
- Keep module imports light: nothing imports `ultralytics` or `openai` at package
  import time (lazy imports inside the impls), so offline tests never need them.

## Tests

- `test_run_context.py`: run dir is fresh and timestamped; two runs in the same second
  get distinct suffixes; `write_json` is atomic (no `.tmp` left); manifest starts with
  `status=running`, ends `completed`; `step_dir(1, "panels")` returns `<run>/1_panels`.
- `test_config.py`: CLI defaults match the dataclass; `--limit 0` and negative
  `--skip-first` are rejected; `--steps panels,stitch` parses to a subset.
