# Task 0003 — Panel extraction step (`1_panels/`)

## Goal

Implement the extraction stage: crop the detected panels from each page, name the
files by Japanese reading order (`panel_0001.png`, `panel_0002.png`, …), and persist
the per-page geometry (`panels.json`: boxes, confidence, reading-order index) that
stitching (task_0007) will consume. This stage produces the run directory
`1_panels/`.

## Context

This is pipeline stage 2 ("extrait les cases dans un dossier 1_pannels" in the idea —
we use the fixed spelling `1_panels/` pending the user's answer on naming). The crops
are the input to character detection (task_0004). The geometry JSON must be saved now
because it is needed again at the end (stage 5) to paste the colorized panels back at
the exact same positions.

## Files

- `pipeline_v1/extraction.py` — pure crop helpers.
- `pipeline_v1/steps/panels.py` — the step: for each input page, detect → order →
  crop → write crops + `panels.json` (and the debug overlay) into `1_panels/<page_stem>/`.
- `pipeline_v1/tests/test_extraction.py`.

## Design

```python
# extraction.py (pure, PIL-only)
def crop_panel(page: Image.Image, box: PanelBox, inset: int = 0) -> Image.Image: ...
def save_panels(page, detections, out_dir, *, prefix="panel") -> list[Path]: ...
```

- `crop_panel` uses `box` rounded to int, clipped to page bounds; `inset` (default 0)
  trims the border pixels when the detector box hugs the panel frame (tunable, kept in
  config as `panel_inset`).
- File naming: `panel_0001.png` … in reading order (zero-padded 4 digits — matches the
  existing `data/panels/` convention).
- `steps/panels.py` flow per page: `detector.detect(page)` → `reading_order(boxes)` →
  `save_panels(...)` → write `panels.json`:

```json
{
  "page": "0134-001.png",
  "page_sha256": "...",
  "detections": [
    {"panel_index": 1, "box": [x1, y1, x2, y2], "confidence": 0.93, "crop": "panel_0001.png"}
  ],
  "reading_order": [1, 2, 3]
}
```

- Also write `1_panels/<page_stem>/overlay.png`: page with numbered rectangles drawn,
  for visual QA.
- The step appends a per-page record to the run manifest (via `RunContext`).

## Tests (`test_extraction.py`)

- Synthetic page (solid background + distinct colored rectangles as "panels", built in
  a test fixture) + known boxes: crops have exactly the expected region content
  (compare cropped pixels), are named in reading order, and the source page is not
  modified.
- `panels.json` round-trips: boxes in the file equal the ones used for cropping.
- `inset` trimming shrinks the crop by the expected amount and stays within bounds.
- A detection whose box exceeds page bounds is clipped, not an error.

## Acceptance criteria

- [ ] Running the step on a synthetic page produces `1_panels/<page>/panel_000N.*`
      numbered in Japanese reading order plus `panels.json` and `overlay.png`.
- [ ] No writes outside the run directory (`RunContext` owns all paths).
- [ ] Tests green; commit.
