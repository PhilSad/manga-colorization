# Task 0008 — Orchestrator, CLI wiring, mock backends

## Goal

Implement `orchestrator.py` (step sequencing, per-step directories, manifest
aggregation with cost totals, partial-run support), wire `run.py` to real backends
(+ `--mock` flag using built-in fakes), and add `mock_backends.py`.

## Context

This is where the five stages become one runnable pipeline with the repo's run
conventions: a fresh timestamped run dir, `1_panels/` → `2_characters/` →
`3_colorized/` → `4_stitched/`, an incremental manifest, and cost accounting
(OpenRouter `cost_usd` measured per call; FLUX self-hosted = $0 + electricity note).

## Files

- `pipeline_v1/orchestrator.py`
- `pipeline_v1/mock_backends.py` — `MockPanelDetector` (canned boxes), `MockCharacterDetector`

- `pipeline_v1/run.py` — wire: parse config → build backends (real unless `--mock`) →
  `PipelineRunner(config, backends).run()`.
- `pipeline_v1/tests/test_orchestrator.py`.

## Design

```python
@dataclass
class Backends:
    detector: PanelDetector
    character_detector: CharacterDetector
    colorizer: Colorizer

class PipelineRunner:
    def __init__(self, config: PipelineConfig, backends: Backends, run_ctx: RunContext): ...
    def run(self) -> Path: ...   # returns run dir; raises on fatal step error
```

Step flow per page (with `--limit` / `--skip-first` applied to the page list first):

1. `panels` → `1_panels/<page>/` (crops, panels.json, overlay) — tasks 0002+0003.
2. `characters` → `2_characters/<panel>.json` + summary — task 0004.
3. `colorize` → for each panel: `atlas.build_filtered_atlas(characters)` then
   `colorizer.colorize(...)` → `3_colorized/<page>/panel_000N.png` + per-call records.
4. `stitch` → `4_stitched/<page>.png` — task 0007.

Manifest schema (aggregates per-step records, mirrors research-method conventions):

```json
{
  "schema_version": 1,
  "pipeline": "panel-wise-flux9b-lora",
  "status": "running|completed|failed|aborted",
  "started_at": "...", "finished_at": null,
  "run_directory": "...", "command": "...",
  "configuration": { ...all PipelineConfig fields... },
  "dependencies": {"python": "...", "pillow": "...", ...},
  "pricing_assumptions": {
    "character_detection": {"model": "google/gemma-4-31b-it", "tier": "openrouter paid", "...": "..."},
    "colorization": {"model": "FLUX.2-klein-base-9B + manga-colorization LoRA", "hosting": "self-hosted Spark", "usd_per_call": 0.0, "note": "electricity only"}
  },
  "steps": {
    "panels":      {"status": "...", "pages": [ ... ]},
    "characters":  {"status": "...", "calls": [ ... ], "totals": {"api_calls": N, "cost_usd": X}},
    "colorize":    {"status": "...", "calls": [ ... ], "totals": {"api_calls": N, "total_latency_s": ...}},
    "stitch":      {"status": "...", "outputs": [ ... ]}
  },
  "totals": {"openrouter_cost_usd": X, "flux_calls": N, "panels_colorized": N,
             "pages_stitched": N, "wall_time_s": ...}
}
```

- `--steps panels,stitch` runs a subset; `--from-step` resumes after a previous failed
  run (reuses the same run dir only when explicitly passed via `--resume <run_dir>` —
  otherwise a new timestamped dir is created; keep it simple: document
  `--steps` + fresh dir as the resume mechanism).
- On `KeyboardInterrupt`/failure: manifest `aborted`/`failed` + error recorded, partial
  artifacts preserved (same pattern as the research methods).

## Tests (`test_orchestrator.py` — all mock backends, offline)

- Full run on a synthetic page: all four step dirs exist and are populated; manifest
  `status=completed`; `totals` reflect 1 page / N panels (mock character detector
  returns 2 characters on panel 1 → atlas contains 2 cells, colorizer got [panel,
  atlas]).
- `--steps characters,stitch` skips `1_panels/`/`3_colorized/` (error when inputs
  missing → manifest `failed`, no overwrite of existing run dirs).
- Cost aggregation: mock character records with `cost_usd` sum into `totals`.
- Failure mid-run (colorizer raises) → manifest `failed` with the step + error named,
  artifacts from earlier steps kept.
