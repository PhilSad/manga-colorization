# Task 0009 — End-to-end test suite (mock backends, synthetic manga page)

## Goal

Deliver the end-to-end tests the user asked for: run the **full pipeline** from an
input page to a stitched page — detection, reading-order numbering, extraction,
character detection, filtered atlas, colorization, stitching, manifest — using mock
backends on a synthetic manga page, fully offline (no OpenRouter calls, no Spark).

## Context

Individual steps are unit-tested in tasks 0001–0008. This suite validates the wiring:
data flows between steps (crops → detection JSONs → atlases → colorized panels →
stitched pages), numbered run directories, manifest completeness, and cost totals.
A separate **manual smoke script** (real YOLO model + real OpenRouter + real Spark
endpoint, one page) is added here as a script but is not part of pytest.

## Files

- `pipeline_v1/tests/synthetic_page.py` — builder for a manga-like synthetic page:
  white background, 3–4 "panels" as gray/outlined rectangles at known coordinates
  (including a right-column stack + a left tall panel so reading order is
  non-trivial), plus a page number in a corner. Deterministic.
- `pipeline_v1/tests/test_end_to_end.py` — the e2e test(s).
- `pipeline_v1/scripts/smoke_real.sh` — documented manual smoke: downloads the real
  YOLO weights, runs the pipeline against `http://spark:3000` + OpenRouter on one
  real page (`--skip-first 3 --limit 1`), prints the run dir + manifest path.
- `pipeline_v1/tests/conftest.py` — add fixtures: `synthetic_page`, `tmp_refs`
  (two tiny reference webp files), `mock_backends`.

## Design

`test_end_to_end.py` (single test function is fine, or a few):

1. Build a synthetic page and a tmp refs dir (`frieren_reference.webp`,
   `fern_reference.webp`).
2. Construct `PipelineConfig` pointing at them, `--mock` backends:
   - `MockPanelDetector` → the known boxes (or, better: run the real
     `reading_order` + extraction on them so numbering is genuinely exercised).
   - `MockCharacterDetector` → panel 1: `["Frieren", "Fern"]`, panel 2: `["Frieren"]`,
     panel 3: `[]` (exercises the empty-detection policy path).
   - `MockColorizer` → returns a solid-color tinted copy of the panel (no HTTP
     server needed for the orchestrator test; the fake HTTP server in task_0006
     covers the client contract separately).
3. Run `PipelineRunner(...).run()`.
4. Assert:
   - run dir contains `1_panels/`, `2_characters/`, `3_colorized/`, `4_stitched/`;
   - `1_panels/<page>/panel_0001.png … panel_0003.png` numbered in reading order and
     `panels.json` boxes match the synthetic layout;
   - `2_characters/` has one JSON per panel with the canned characters and
     `cost_usd` values;
   - colorized outputs exist; the atlas sent for panel 1 contained only
     Frieren+Fern (the mock colorizer records the atlas labels it received — e.g.,
     `MockColorizer` inspects the atlas path via `atlas.refs_for_characters`, or the
     mock just records which atlas path it got and the test validates the atlas file
     with `refs_for_characters`);
   - stitched page: color inside boxes, grayscale outside (pixel assertions);
   - manifest `status=completed`, `totals.openrouter_cost_usd` == sum of the canned
     costs, `totals.panels_colorized == 3`, `totals.pages_stitched == 1`.

Also add a `--mock` pipeline run test via `run.py` subprocess (fast, validates the CLI
wiring end to end without pytest internals).
